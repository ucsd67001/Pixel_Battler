## 2. 決めたこと（2026-11-25）

| こと | 決めたこと |
|---|---|
| 種類 | **武器**：剣・斧・槍・銃・杖。**防具**：盾・兜・鎧。あわせて8種類 |
| 作り方 | **写真から作る**。「写真から作る」の画面で、はじめに**ロボかアイテムか**を選ぶ |
| 種類の決め方 | **AI が写真から決める**（鉛筆なら槍、なべのふたなら盾、のように。何が生まれるか分からない楽しさ）。ほしい種類が出ないときの「種類をえらんで作る」は、あとで考える |
| 強さの決め方 | **ロボと同じ**。AI が決めるのは種類・名前・説明・見た目だけ。数字とランク（C〜S）は、写真の印からサーバーが決める |
| 身につける数 | **武器か防具のどれか1つだけ**（攻めるか、守るか、を選ぶ遊び） |
| 置き場 | ガレージのような**アイテムの置き場**を作る。30個まで（家族は100個まで。ガレージと同じ） |
| 作れる回数 | 写真から作る回数は、**ロボとアイテムを合わせて**数える（いまの一日10回・家族30回のまま。AI の料金を今と同じに保つ） |
| 何体が持てるか | 一つのアイテムを、**何体のロボでも同時に**持てる（持ち物は自分のもので、どのロボにも貸せる。つけかえの手間がない） |
| 効くモード | **すべてのモード**（ストーリー・コンピュータと対戦・ふたりで対戦）。レベルは遊んだ量で強くなるので、ふたりで対戦では使わないが、アイテムは写真1枚でだれでも手に入るので、不公平になりにくい |
| ロボの形 | **ヒト型・イヌ型・トリ型の3つのまま**（プレイヤーのロボも）。アイテムは、形ごとに持ち方を変える（4章） |
| もとの武器 | 11/23 に素手にしたときの「そのロボがもともと持っていた武器」（設計図の `parts.weapon`）は、**アイテムとしては使わない**。見た目は今の素手のまま。ただし `parts.weapon` は体つきの計算（`lookSeed`）に使っているので、設計図からは消さない |
| 杖の見た目 | **魔法っぽく**（持ち主の希望）。5章 |
| 章の敵 | **アイテムを持たせない**（2026-11-26、持ち主が「いまのまま」）。アイテムを持つとストーリーのボスに勝ちやすくなる（約50% → 約63%）が、集めたアイテムの手ごたえになり、行きづまりにくくなるので、そのままにする |

## 3. 種類ごとの持ち味（段階1で作った。2026-11-25。`src/game/items.ts`）

数字が上がるだけだと、どれも同じになる。種類ごとに、小さな持ち味をつけた。
一つしか持てないので、**武器と防具のどれを選んでも損をしない**ように、`npm run sim` で合わせた。

| 種類 | 画面の名前 | | 持ち味（総合力 100 のとき） |
|---|---|---|---|
| 剣 | けん | 武器 | こうげき +14% |
| 斧 | おの | 武器 | こうげき +24%。ただし自分のこうげきが 12% の確率で空ぶり（必殺技とカウンターは空ぶりしない） |
| 槍 | やり | 武器 | 相手のぼうぎょを 30% 無視する |
| 銃 | じゅう | 武器 | 先に動ける（「先手」の特性と同じ。最初の一撃 1.5倍は無し）。必殺ゲージのたまり方 +45% |
| 杖 | つえ | 武器 | スキルのパワー +55%（スキルは何ターンかに一度なので大きめ）。自分の番のたびに SP +8 |
| 盾 | たて | 防具 | 受けるダメージが、いつも 11% へる。ガードすると、さらに 30% へる |
| 兜 | かぶと | 防具 | HP +10%。受ける会心の一打の確率が 60% へり、会心の大きさも小さくなる |
| 鎧 | よろい | 防具 | ぼうぎょ +32% |

- **画面の名前はひらがな**：剣・斧・槍・銃・杖・盾・兜・鎧は、どれも小学校で習わない漢字のため（英語の名前 SWORD・AXE… もつける）
- **アイテムの強さ**：ロボと同じく、写真の印から総合力（92〜108）とランク（C〜S）を決める。持ち味の大きさは総合力に比例する（C の 92 で約0.92倍、S の 108 で約1.08倍）
- HP・こうげき・ぼうぎょが上がる分は、バトルの前に数字に入れる（`withItem`）。ほかの持ち味は、バトルの計算（`battle.ts`）が `gearOf` で読む
- アイテムを持っていないバトルは、いままでとまったく同じ結果になる（さいころのふり方も同じ）
- **盾は、はじめ「ガードの効き目が上がる」だけにしたら、ほとんど効かなかった**（持たないロボに 49.9%。ガードは、バトルの中であまり使わないため）。そこで「いつも少しへる」を足した

### 釣り合いの確かめ（`npm run sim` の「アイテム」）

- **持つ 対 持たない**（同じくらいのロボどうし。先と後を半分ずつ。Lv1・10・25 をまぜる）：どの種類も **約60%**（59〜61%）。レベルが2〜3上なのと同じくらい
- **持つどうし**（8種類 × 8種類）：どの組み合わせも 46〜53%、種類ごとの平均は 47〜51%（引き分けの分だけ 50% より少し下）。じゃんけんのように強すぎる組み合わせは無い
- **コンピュータと対戦**：アイテムを持ったロボは、コンピュータの敵（アイテムなし）に約63%勝つ（持たないときは約50%）
- **ストーリー**（1体で通しで進める）：10章までに行きづまる人が 約32% → **約18%**、1章あたりの戦う回数が 約16戦 → 約12戦。アイテムを持つと、ストーリーはかなり楽になる（敵はアイテムを持たないため。これでよい、と持ち主が決めた。2章の表）
- **ストーリーのボス**（同じレベル）：持たないと約50%、アイテムを持つと **約63%**（段階5で確かめた。2026-11-26）
- アイテムが無いときの釣り合い（敵ごと・属性ごと・レベル・ストーリー）は、前と変わらない

## 4. 形ごとの持ち方（3D）

| | ヒト型 | トリ型（浮かぶ手が2つ） | イヌ型 |
|---|---|---|---|
| 剣 | 右手 | 浮かぶ手 | 口にくわえる |
| 斧 | 右手 | 浮かぶ手 | 口にくわえる |
| 槍 | 右手 | 浮かぶ手 | 口にくわえる（横にして） |
| 銃 | 右手 | 浮かぶ手 | せなかにのせる（砲台） |
| 杖 | 右手 | 浮かぶ手 | 口にくわえる（先が光る） |
| 盾 | 左手 | 浮かぶ手 | 体の横（肩） |
| 兜 | 頭 | 頭 | 頭 |
| 鎧 | 胴 | 胴（まるい体） | 胴（馬のよろいのように） |

- **アイテムの設計図は、形に関係なく一つ**。写真から決めるのは、種類・名前・色・形の特ちょう（長さ・太さ・かざりなど）だけ。どの形のロボが持っても、同じアイテムに見える。持ち方は 3D の側で、形ごとに決める
- イヌ型の武器は、前（11/23 より前）のように体の部品に**置きかえない**。写真から作った武器の形と色が、そのまま見えるようにするため（くわえる・せなかにのせる）
- 一つしか持たないので、両手の組み合わせ（武器と盾を両方）は考えなくてよい

## 5. アタックの動き（武器の種類ごと）

| 武器 | 動き（段階5で作った。2026-11-26。`src/three/stage.ts` の `attack`） |
|---|---|
| なし・防具 | いまと同じ、こぶしでなぐる（イヌ型は体当たり・トリ型は浮かぶ手でなぐる） |
| 剣 | かけよって、ふりおろす。属性の色の弧 |
| 斧 | かけよって、たてに重くふりおろす。大きな弧・足もとに火花・画面がゆれる |
| 槍 | かけよって、つく。属性の色の光の筋が、相手をつきぬける |
| 銃 | その場からうつ（じゅうの口から光の玉。イヌ型は、せなかの砲台から） |
| 杖 | **魔法**：杖の先に魔法陣（二重の円・星・小さな玉。くるくる回る）が開き、属性の色の光の玉が相手へ飛ぶ。当たると光がはじける。スキルのときは、魔法陣も玉も大きい（イヌ型は、くわえた杖の先から） |

- 動きは「武器の種類 × 形」ではなく、**武器の種類ごと**に作り、形のちがいは持つ場所だけにする（作る量をへらす）。体の動き（ふりかぶる・つく・ねらう）は、形ごとの前からの動き
- 魔法陣は、真横に向けるとカメラから細い線に見えるので、カメラのほうへ半分ほど向けている
- 効果音は、杖だけ「まほう」（キラキラ）を足した（`src/lib/sfx.ts`）。ほかは前からの音
- スキル・必殺技の演出は、いまのまま（必殺技の型ごと）。必殺技の光も、武器の先（tip）から出る

## 6. データの形

| 置き場 | 中身 | 書く人 |
|---|---|---|
| Firestore `users/{uid}/items/{写真の印}` | アイテム（`Item`：設計図・ランク・総合力・写真の縮小・作った日・ai か local か）。段階2で作った | サーバーだけ（`/api/items`）。見る・消すのは本人（`firestore.rules`） |
| Firestore `specs/i1_{写真の印}` | アイテムの設計図の取り置き（同じ写真には同じアイテム。ロボの取り置き `k2_…` とは名前を分ける） | サーバーだけ |
| ガレージのロボの `itemSeed` | いま持たせているアイテムの写真の印（一つだけ）。段階4で作った。アイテムを置き場から消すと、持っていないのと同じになる（ロボの側は書きかえない） | サーバーだけ（`/api/robots/equip`） |

- **アイテムの設計図**（`ItemSpec`。`src/game/items.ts`）：種類（kind）・名前・説明・写真に写っていたもの（motif）・色3つ（primary＝本体、secondary＝持ち手やふち、accent＝かざりや光るところ）・大きさ（size：small／medium／large）・かざり（deco：plain／gem／spikes／wings／stripes）。大きさとかざりは、段階4の 3D で使う

- ロボと同じく、**数字はサーバーが写真の印から決め直す**（画面から届いた数字は使わない）。特別な写真のしるしは受け取らない
- **ふたりで対戦・だれかのロボ**として出すときは、アイテムの設計図もいっしょに送る（写真・写っていたもの・写真の印は送らない）。受け取った画面は、ロボと同じように数字を出し直す（`fairChar` と同じ考え方）
- 手元（`npm run dev`）では、このスマホの中（localStorage の `pb.items.v1`）に置く。設計図の取り置きは `.cache/items/`（`.cache/specs/` はロボだけ。手元の rival とランキングが、ロボの設計図として読むため）

## 7. 作る順（段階）

1. **決まりと数字**（2026-11-25 に作った）：アイテムの型・8種類の持ち味・強さの計算（`src/game/items.ts`）。バトルの計算に持ち味を入れ、`npm run sim` で、武器と防具のどれを選んでも勝率がそろうように合わせた（3章）。画面には、まだ何も出ない
2. **写真から作る**（2026-11-25 に作った）：はじめに「ロボ」か「アイテム」かを選ぶ。AI への指示（種類・名前・見た目を写真から）、サーバーの窓口（`/api/items`。回数はロボと合わせて数える）。くわしくは 7.1
3. **アイテムの置き場**（2026-11-26 に作った）：一覧・大きく見る・消す。タイトルとスマホのメニューに入り口。3D で見るのは段階4（持たせる見た目といっしょに作る）。くわしくは 7.2
4. **持たせる**（2026-11-26 に作った）：ガレージやロボを選ぶ画面で、アイテムを一つ選んで持たせる・外す。3D の見た目（8種類 × 3つの形の持ち方）。くわしくは 7.3
5. **バトルで使う**（2026-11-26 に作った）：持ち味が効く・武器ごとのアタックの動き（杖は魔法）。ストーリー・コンピュータと対戦・ふたりで対戦・だれかのロボ、のすべて。最後にもう一度、釣り合いを確かめた。くわしくは 7.4

段階1と5は、数字の決まりがいっしょなので、5の「効き目」は1で先に作って sim で確かめておく（画面に出すのは5）。

### 7.1 段階2で作ったもの（2026-11-25）

- **画面**（`src/ui/Create.tsx`）：「写真から作る」の上に「ロボ」「アイテム」の切りかえ。アイテムを選ぶと、読みとりの文がアイテム用になり、できたら写真を丸いわくで見せて、カード（`src/ui/ItemCard.tsx`）で紹介する。カードには、種類（武器か防具・ひらがなの名前）・ランク・説明・持ち味（数字つき。`itemEffectText`）。3D はまだ（段階4）
- **AI への指示**（`server/items.ts` の `analyzeItem`）：写真のいちばん目立つものから、8種類のどれかを形で選ぶ（細長い→けん・やり・つえ、丸くて平たい→たて など）。名前と説明に、習わない漢字（剣・盾など）を書かない。それでも入っていたら、ロボと同じく、名指しして一度作り直し、残れば文だけ書き直す。特別な写真のしるしは、アイテムでは いつも 0（まだ決めていないため）
- **サーバー**（`/api/items`）：ログインが要る。同じ写真のアイテムがもうあれば、それを返す（回数に数えない）。置き場がいっぱい（30個、家族は100個）なら 409。作る回数は、ロボと同じ数え方（`countUp`）で合わせて数える。AI につながらなければ、写真の印と色から作る（`localItemSpec`。source は local）
- **アイテムの置き場**（`src/game/itemBox.ts` の `useItemBox`）：本番はクラウド、手元はこのスマホの中。一覧を見る画面は、まだ無い（段階3）
- 手元で試した（2026-11-25）：えんぴつの絵から「えんぴつスピア」（やり・ランク B）。同じ絵をもう一度読ませると「前にも同じアイテム」。スマホの幅で、はみ出さない。ロボを作る道も、前のまま動く。**本番（ログイン・クラウドの置き場・回数）では、まだ試していない**

### 7.2 段階3で作ったもの（2026-11-26）

- **画面**（`src/ui/Items.tsx`。上の帯は ITEMS）：ガレージと同じ形。左に選んだアイテム（写真を丸いわくで大きく見せる）、下に一覧、右にカード
- **しぼりこみ**：一覧の左に「すべて・武器・防具」と、それぞれの数
- **消す**：「置き場から消す」（たしかめの窓のあと）。クラウドでは本人だけが消せる（`firestore.rules`）
- **作る**：「写真からアイテムを作る」で、写真から作る画面へ（はじめから「アイテム」が選ばれている）。置き場がいっぱいのときは押せない。まだ一つも無いときは、作り方の説明と「アイテムを作る」
- **入り口**：タイトル（アイテムが一つでもあるとき、ガレージのとなりに「アイテム（◯個）」）と、スマホのメニュー（「ロボとアイテム」の中の「アイテムの置き場」）
- スマホの幅では、丸いわくを小さくして、下の一覧と重ならないようにした
- 手元で試した（2026-11-26）：見本のアイテム6個で、一覧・しぼりこみ・選ぶ・消す・作る画面へ・スマホのメニューから開く・空のとき。**本番（クラウドの置き場を見る・消す）では、まだ試していない**

### 7.3 段階4で作ったもの（2026-11-26）

- **持たせる画面**（`src/ui/ItemSlot.tsx`）：ガレージと、ロボを選ぶ画面（コンピュータと対戦・ストーリー）のカードの下に「ITEM」の欄。持っているアイテム（写真・名前・種類・ランク・持ち味の数字）と「かえる」「外す」。持っていなければ「アイテムを持たせる」。押すと置き場のアイテムが並び、一つ選ぶと持たせる
- **データ**：ロボに書くのは、アイテムの写真の印（`itemSeed`）だけ。強さは、置き場のアイテムから決める（同じアイテムを何体に持たせても、どれも同じ強さ）。クラウドではサーバー（`/api/robots/equip`）が書く。持たせるアイテムが、その人の置き場にあるかを確かめる
- **3D**（`src/three/itemModel.ts` の `attachItem`。`buildRobot(spec, item)`）：
  - 武器の形：けん（細い刃と、光る線）・おの（扇の形の刃。柄から横へ）・やり（長い柄と、光る穂先）・じゅう（光の玉をうつ筒）・つえ（光る玉と、まわりの輪。魔法の杖）
  - 防具の形：たて（下がとがった涙形）・かぶと（丸い兜と、ひさし・とさか）・よろい（ヒト型は胸と背中の板・肩の当て・ベルト。イヌ型は背中と横と胸の板。トリ型は体のまわりの帯と板）
  - 色は、アイテムの色3つ（本体・持ち手・かざり）。大きさ（小・中・大）で長さが変わる。かざり（宝石・とげ・羽・しま模様）を付ける
  - 持ち方は4章の表のとおり。イヌ型の武器は口に横にしてくわえ、じゅうは背中の砲台。トリ型のかぶとは、目をかくさないように浅くかぶせる
  - こうげきの光が出るところ（tip・muzzle）も、武器の先にする（段階5のアタックの動きで使う）
- 見本は `?showroom&items=humanoid`（`floater`・`beast`）で8種類をならべて見る。`&kinds=sword,axe` でえらび、`&size=large`・`&deco=gem` も使える
- バトルで持ち味が効くのと、バトルの 3D で持つのは、段階5で作った（7.4）
- 手元で試した（2026-11-26）：3つの形 × 8種類の見た目。ガレージで、持たせる・同じアイテムを別のロボにも持たせる・かえる・外す・スマホの幅。**本番（/api/robots/equip）では、まだ試していない**

### 7.4 段階5で作ったもの（2026-11-26）

- **どのモードでも効く**：バトルに出すときに、持たせているアイテムを置き場から読んで、ロボに持たせる（`useItemBox().arm`。中身は `withItem`）
  - コンピュータと対戦：ロボを選ぶ画面の「◯◯で戦う！」と、写真から作ったあとの「バトルへ！」
  - ストーリー：レベルの分をかけたあとに持たせる（`src/ui/Story.tsx`。置き場を読み終えるまで待つ）
  - ふたりで対戦：部屋に入るときに持たせて送る（`src/net/room.ts` の `publicChar`）。送るのは、アイテムの設計図と写真の印だけ（アイテムの写真・写っていたものは送らない）。受け取った画面は、設計図を整え、強さを写真の印から出し直す（`fairItem`。総合力を書きかえて送っても効かない。特別な写真のしるしは受け取らない）。先に動く人を決めるときも、じゅうを数える
  - だれかのロボ：サーバー（`/api/rival`）が、持ち主の置き場からそのロボのアイテムを読み、設計図（写っていたものは消す）と総合力・ランクを送る（`server/rival.ts` の `toRivalItem`）。習わない漢字が残っているアイテムは持たせない。置き場から消えていれば素手
- **バトルの画面**：HP の下の欄に、持っているアイテムの種類（「つえ」など）を出す。押すと、名前・ランク・持ち味の数字
- **3D**：バトルの二体も、持っているアイテムを持つ（`setFighters(a, b, itemA, itemB)`）。アタックの動きは5章の表のとおり
- 画面の「バトルで持ち味が効くのは、もう少し先です」は消した
- 見本：`?showroom&battle=5&item=staff` で、アイテムを持ったロボのバトル（`&foeitem=gun` で敵にも、`&foe=9` で敵のロボをえらぶ）
- **釣り合い**（`npm run sim`）：持つ 対 持たない は、どの種類も 59〜62%。コンピュータの敵に 約62%。ストーリーのボス（同じレベル）に 約63%（持たないと約50%）。アイテムが無いバトルの結果は、前と同じ
- 手元で試した（2026-11-26）：
  - 3つの形 × 武器5種類と素手・たてで、アタックとスキルの動きが最後まで動く（エラーなし）
  - 杖の魔法：ヒト型は画面で見た（魔法陣・光の玉・はじける光）。イヌ型は、ブラウザの画面がかくれていて写真が新しくならなかったので、口の杖の先の明るさが上がることを数字で確かめた（**イヌ型の魔法は、まだ目で見ていない**）
  - コンピュータと対戦・ストーリーで、持たせたアイテムが効く（数字・HP の下の欄・3D）
  - ふたりで対戦：部屋に送る形と、作り直し（写真が消える・総合力を書きかえても戻る）を、部品で確かめた。**二つのタブでの対戦は、まだ試していない**
  - だれかのロボ：手元の `/api/rival` で、アイテムつきのロボが届き、敵として持つ
  - **本番では、まだ試していない**（`/api/rival` が置き場を読むところ・クラウドの置き場から持たせるところ）
